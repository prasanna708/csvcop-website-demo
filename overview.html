Three programs, one encrypted source of truth

CSVCOP is deliberately simple to reason about: an application decides, a service enforces, an agent guards the session, and the firewall built into Windows carries the network policy — and they coordinate only through encrypted files that the service protects.

What CSVCOP is

A lockdown you switch on, and a network you decide

A laboratory workstation has to be usable by operators and unchangeable by them, and it should talk only to the machines it needs. 21 CFR Part 11 Controls turns the long list of Windows settings behind the first half into 97 numbered controls, each switched on or off by itself and described in plain language. Micro-segmentation answers the second half: which programs on the PC may talk to which machines.

  • Applied to every user of the machine, including accounts created later
  • Held in place by a service the operator cannot stop: controls and firewall rules alike
  • Every change, tamper event, blocked attempt and refused connection written down
Architecture

What runs where

Three programs with one job each. None of them needs a network, and the application does not need to stay open.

CSVCOP application

21Part11.exe · elevated, on demand

Where administrators sign in, configure and apply controls, write the network policy, manage users and USB whitelists, activate the licence and print reports.

Watchdog service

CsvCopWatchdog.exe · SYSTEM · always on

Enforces the master every 30 seconds, holds the network policy in Windows Firewall, reverses tampering, protects the data folders, supervises the session agent, keeps the licence honest and writes the logs.

Session agent

CsvCopAgent.exe · one per signed-in user

Lives inside each desktop session, where a service cannot: keyboard, clipboard, toolbar, rename box and Recycle Bin — and the “Blocked by admin” note.

Encrypted masters & logs

C:\ProgramData\CsvCop · DPAPI, machine-bound · SYSTEM and administrators only

The control master, users, USB whitelist, network policy, licence and clock records, plus the application, security and heartbeat logs. The application writes here; the service reads, enforces, backs up and restores. The two never call each other directly.

The 30-second cycle

What the service does, every half minute, for ever

  1. Heartbeat — a dated line proving the service is alive.
  2. Session agents — every signed-in session has one; their blocked-attempt reports move into the security log.
  3. Licence — record the latest time seen, evaluate the licence, log any change of state.
  4. Compliance check — read the live value of every applied control and compare it with the master.
  5. Restore — put back anything that differs, on the machine and in every user profile, and log the values found and restored.
  6. Network policy — hold Windows Firewall to the policy: put back rules changed outside CSVCOP, roll back a change nobody committed within five minutes, record the connections refused.
  7. Backup — refresh the protected backup of the master.
How it tells tampering from a legitimate change. When an administrator applies a configuration, the application writes a new version stamp beside the master. The service sees the version change and applies the new configuration. The same difference with an unchanged version is tampering — reversed and logged. No false alarms for your own changes; no silent acceptance of anyone else's.
What each side sees

Honest scope. CSVCOP controls the Windows workstation and records what happens there. It does not validate your instrument software, sign your electronic records, or manage your training. It makes the workstation part of your compliance story simple to prove.

Evidence

What you can hand to the auditor

The same reports for both modules, and the same audit trail underneath them.

Configuration and changes

System Controls Summary: every control and its state, as applied. Control Change History: who switched what, when and why.

Activity and audit trail

User Activity Log, User Summary, and the Audit Trail of every event, filtered by date and user.

USB

USB Whitelist Summary of the devices let in and their schedules; USB Whitelist Activity of every change to the list.

Network

Micro-segmentation Policy: the rules in force. Micro-segmentation Activity: every change and every refused connection.

Nine reports, each a click from PDF with your logo, the Equipment ID and the date; the two network reports come with the Micro-segmentation module. Tamper events are also mirrored to the Windows Event Log.

Start-up & resilience

Protection that is there from the first second

A security service that is late, or easy to stop, is a hole. CSVCOP is built to be neither: it starts before the sign-in screen, and Windows treats even a deliberate stop as a failure to recover from.

At boot
The service starts with the other automatic services, before the sign-in screen — not delayed.
At sign-in
The service receives the sign-in event and starts the session agent for that user at once.
If the agent ends
The service starts it again within a second or two; a crash-loop is paced, never spun.
Can an operator end it?
No. A standard user can see the agent but not end, suspend or tamper with it.
If the service stops
Windows restarts it after 5, 10 and 30 seconds.
If the master is deleted
Restored from the protected backup on the next cycle, and the deletion logged.
Deployment

One installer, modest requirements

Windows

7 SP1 through 11, 32- or 64-bit.

Runtime

.NET Framework 4.5 or later — built into Windows 8 and later.

Install

One MSI; administrator rights for installation and configuration.

Network

None required — for operation or for activation. The licence key names the modules the PC has.

Some controls take effect immediately; some at the user's next sign-in or after Explorer restarts. Each control's description says which.
